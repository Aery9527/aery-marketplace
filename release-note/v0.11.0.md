## 概覽

`v0.11.0` 處理一個結構性問題：`.claude-plugin/marketplace.json` 同時扮演兩個角色——Claude Code 與 Copilot CLI 的產品目錄，以及 Codex 封裝管線的建置清單。`aery-claude-code` 只需要後者，但待在那個檔案裡就被迫承擔前者，導致一個「教 Codex 去驅動 Claude Code」的 bundle 反而被推銷給 Claude Code 自己。

解法是讓兩份目錄各自宣告只有自己能安裝的 bundle：所有 host 都能用的仍以 `.claude-plugin/marketplace.json` 為準，只有 Codex 能用的改宣告在新增的 `.agents/plugins/codex-only-bundles.json`，同步腳本與驗證腳本讀兩者的聯集。同一個 bundle 同時出現在兩份檔案會被直接拒絕。整個 repo 共用的版本號仍留在 Claude 目錄，因此 release 流程不受影響。

本版同時把 `claude-code-bridge` skill 的指引鏈收斂到功能層面。該 skill 是另一個專案的反向移植，但 agent 在使用它的當下不需要知道這件事——那些脈絡只對維護者有意義，現已全數集中在 `docs/claude-code-bridge/UPSTREAM-PARITY.md`，並且不再隨 skill 一起發佈到安裝端。

## 升級注意事項

- `aery-claude-code` 不再出現在 `.claude-plugin/marketplace.json`。曾在 Claude Code 或 GitHub Copilot CLI 安裝過它的人，會發現它從 catalog 中消失。這是刻意的：該 bundle 的用途是從 Codex 呼叫 Claude Code，在 Claude Code 自身沒有意義。
- Codex 端不受影響。`aery-claude-code` 仍完整列在 `.agents/plugins/marketplace.json`，package 內容、plugin-root overlay 與 `plugin.json` 的 version 同步行為都與先前一致。
- 新增 bundle 時要先決定它屬於哪一份目錄。規則寫在 `AGENTS.md`：Claude 側 host 用得到的宣告在 `.claude-plugin/marketplace.json`，只有 Codex 能用的宣告在 `.agents/plugins/codex-only-bundles.json`，不得同時出現在兩邊。
- `skills/claude-code-bridge/UPSTREAM-PARITY.md` 已移至 `docs/claude-code-bridge/UPSTREAM-PARITY.md`，安裝後的 skill 目錄不再包含它。

## 功能

## 修正

- 讓同步腳本與驗證腳本對畸形或重複的 bundle 宣告採取一致行為。驗證腳本先前會把缺少 `plugins` 的目錄靜默視為空、把重複宣告的 bundle 處理兩次，與同步腳本的拒絕行為不一致（`fix(scripts): reject a malformed or duplicated bundle declaration in both scripts`）。
- 修復驗證腳本的測試套件，並讓缺少 `plugins` 陣列的宣告直接指名問題檔案，而不是回報一個指向無關程式行的 `Cannot index into a null array`。同時補上三個既有 fixture 缺少 plugin manifest 而長期失敗的問題（`fix(scripts): restore the verifier test suite and name a malformed declaration`）。

## 重構

- 把反向移植的來歷從 `claude-code-bridge` 的指引鏈中移除，讓 `SKILL.md`、command 檔與 runtime 文件只談功能。agent 使用該 skill 時不需要這些脈絡，它們只是雜訊（`refactor(claude-code-bridge): keep port history out of the agent-facing guidance`）。
- 把 `UPSTREAM-PARITY.md` 移出 skill 目錄。skill 目錄底下的所有內容都會隨它一起發佈，因此這份純維護紀錄原本會以 781 行、且沒有任何連結指向它的形式進入每一次安裝（`refactor(claude-code-bridge): keep the maintenance record out of the distributed skill`）。
